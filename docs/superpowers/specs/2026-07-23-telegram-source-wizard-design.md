# InfoService: удобное Telegram-меню и пошаговая настройка источников

## 1. Цель и границы

Цель изменения — убрать из пользовательского Telegram-интерфейса необходимость
вводить JSON и сделать основные действия понятными без чтения документации.
Навигация сочетает системные команды Telegram и inline-кнопки. Добавление и
редактирование источников выполняется пошагово отдельными сообщениями.

В первую итерацию входят только четыре стабильных источника:

- RSS/Atom;
- публичный Telegram-канал;
- GitHub releases и события пользователя;
- Hacker News.

Источники по-прежнему принадлежат конкретному отчёту. Общего каталога
пользовательских источников и повторного подключения одного источника к
нескольким отчётам не будет.

Beta- и optional-адаптеры остаются в backend и не удаляются из схем данных.
В мастере добавления они не показываются. Существующие записи таких типов можно
просматривать, включать, отключать и удалять, но их редактирование через JSON
больше не предлагается.

## 2. Навигация и команды

При запуске бот регистрирует системное меню команд Telegram:

- `/start` — начать работу или повторить онбординг;
- `/menu` — открыть главное меню;
- `/reports` — показать отчёты;
- `/newreport` — создать отчёт;
- `/sources` — выбрать отчёт и управлять его источниками;
- `/settings` — открыть настройки пользователя;
- `/help` — показать команды, возможности и короткие примеры;
- `/cancel` — отменить текущий мастер.

Главное меню остаётся гибридным: все частые действия доступны через
inline-кнопки, а команды обеспечивают быстрый переход из любого места.
Предлагаемый набор кнопок: «Мои отчёты», «Новый отчёт», «DeepSeek»,
«Настройки» и «Помощь».

Каждый вложенный экран содержит доступные по смыслу кнопки «Назад»,
«Главное меню» и «Отмена». Бот по возможности редактирует существующее
служебное сообщение вместо добавления нового. Пользовательские текстовые ответы
остаются отдельными сообщениями, поскольку Telegram не поддерживает текстовые
поля внутри inline-клавиатуры.

## 3. Общий сценарий мастера источника

Мастер запускается только из выбранного отчёта:

1. Пользователь нажимает «Добавить источник».
2. Бот показывает четыре стабильных типа с кратким пояснением.
3. Пользователь выбирает тип и получает первый вопрос с примером корректного
   ответа и индикатором шага.
4. После текстового ответа бот проверяет и сохраняет значение в черновике, затем
   показывает принятое значение и явную кнопку «Далее →».
5. Следующий экран предлагает использовать значения по умолчанию либо открыть
   «Дополнительные настройки».
6. После дополнительных настроек также показывается кнопка «Далее →».
7. Перед записью бот показывает итоговую карточку с кнопками «Сохранить
   источник», «Изменить», «Назад» и «Отмена».
8. Только «Сохранить источник» создаёт или изменяет запись в БД.

Кнопка «Назад» возвращает на предыдущий логический шаг и сохраняет остальные
введённые значения. «Отмена» и `/cancel` очищают черновик из любого состояния,
не создавая частичных записей.

Черновик содержит:

- идентификатор отчёта;
- идентификатор источника при редактировании;
- тип источника;
- текущий экран;
- нормализованные значения полей;
- историю пройденных экранов;
- режим создания или редактирования.

## 4. Вопросы для стабильных источников

### RSS/Atom

Обязательный ввод — URL ленты. Бот проверяет HTTP(S)-схему и существующую
SSRF-защиту. Отображаемое название берётся из метаданных ленты, а если получить
его безопасно не удалось — из hostname URL. Пользователь может изменить
название вручную.

Дополнительные поля:

- отображаемое название;
- категория.

Настройка внутреннего `content_extractor` в первой итерации в Telegram не
показывается и использует backend-значение по умолчанию.

### Telegram

Обязательный ввод — публичный username, `@username` или ссылка вида
`https://t.me/username`. Бот нормализует значение до username. Приватные
пригласительные ссылки и пользовательские сессии не поддерживаются.

Дополнительные поля:

- категория;
- число проверяемых сообщений: 10, 20 или 50, по умолчанию 20.

### GitHub

Первый экран предлагает два варианта:

- релизы репозитория;
- события пользователя.

Для релизов принимается ссылка `https://github.com/owner/repo` либо пара
`owner/repo`. Для событий принимается username или ссылка на профиль.

Дополнительное поле — категория.

### Hacker News

Источник не требует обязательного текстового ввода и может быть сразу добавлен
с настройками по умолчанию:

- проверить 30 верхних публикаций;
- минимальный рейтинг 100.

Дополнительные поля:

- количество публикаций в допустимом диапазоне backend-модели;
- минимальный рейтинг;
- категория.

## 5. Редактирование и отображение

Карточка источника показывает человекочитаемые значения, а не внутренний JSON:
тип, адрес или цель, категорию, лимиты и состояние.

Кнопка «Изменить» открывает список доступных полей. Пользователь выбирает одно
поле, вводит новое значение и возвращается к итоговой карточке. Повторное
прохождение всего мастера не требуется. Изменение типа существующего источника
не поддерживается: для этого источник удаляют и создают заново.

Для beta- и optional-источников, которые уже существуют в БД, карточка
показывает безопасное краткое описание и действия «Включить/Отключить» и
«Удалить». Кнопки создания и редактирования для них отсутствуют.

## 6. Валидация и ошибки

`SourceCatalog` и существующие Pydantic-модели остаются единственной
канонической границей валидации перед сохранением. Мастер преобразует
пользовательские ответы в словарь конфигурации и не обходит эту проверку.
В JSONB хранится прежний нормализованный формат, поэтому worker и Horizon
adapter не меняют контракт.

Ошибки отображаются на уровне конкретного поля. Сообщение содержит:

- что не удалось принять;
- короткую причину без внутренних traceback;
- пример корректного значения;
- предложение повторить ввод или отменить мастер.

Ошибка не очищает черновик и не сбрасывает пользователя на первый шаг.
Недоступный отчёт или источник обрабатывается существующей owner-scoped
проверкой. Превышение лимита источников объясняется до попытки сохранения.

## 7. Компоненты реализации

Изменение разделяется на небольшие компоненты:

- регистрация `BotCommand` и обработчики верхнеуровневых команд;
- клавиатуры навигации и мастера;
- русские тексты, описания полей и примеры;
- описание четырёх форм источников;
- FSM-контроллер переходов вперёд, назад, отмены и подтверждения;
- парсеры пользовательского ввода для каждого стабильного типа;
- форматирование итоговых карточек;
- существующий `ReportRepository` для owner-scoped сохранения.

Форма каждого источника описывает обязательные и дополнительные поля,
значения по умолчанию, парсер, формат сообщения и порядок шагов. Общий
контроллер управляет навигацией, но не содержит условные ветки для всех деталей
каждого адаптера.

Текущий `MemoryStorage` остаётся в границах этой итерации. Незавершённый мастер
может быть потерян при рестарте процесса, но частичная сущность в БД при этом не
создаётся. Переход на Redis или постоянное FSM-хранилище является отдельной
эксплуатационной задачей.

## 8. Тестирование

Автоматические тесты покрывают:

- регистрацию полного списка команд и их русских описаний;
- открытие главного меню каждой командой;
- `/cancel` и кнопку «Отмена» из каждого состояния мастера;
- переходы «Далее», «Назад» и сохранение введённых значений;
- основной и расширенный сценарий каждого из четырёх типов;
- нормализацию RSS URL, Telegram username и ссылок GitHub;
- применение значений Hacker News по умолчанию;
- поле-специфичные сообщения об ошибках без очистки черновика;
- итоговую карточку без JSON;
- редактирование одного поля;
- owner-scoped доступ к отчётам и источникам;
- отсутствие beta- и optional-типов в каталоге создания;
- управление ранее сохранённым beta-источником без JSON-редактирования;
- регрессию существующих обработчиков, repository и source validation.

## 9. Критерии готовности

Изменение готово, когда пользователь может открыть системное меню команд,
создать любой из четырёх стабильных источников без знания JSON, вернуться на
предыдущий шаг, отменить действие, увидеть понятную ошибку, проверить итоговую
карточку и изменить отдельное поле. Ни один новый пользовательский экран не
просит JSON или не показывает внутренние названия конфигурационных полей.
